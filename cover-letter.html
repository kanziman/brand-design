hwanghkt@naver.com · github.com/kanziman

금융 데이터 수집·처리 파이프라인을 구축하고, 국내 자동차 대기업의 글로벌 콘텐츠 플랫폼을 개발·운영해 온 백엔드 엔지니어입니다. 다양한 데이터 소스를 연동하고, 여러 국가와 5개 리전에 걸친 서비스의 확장과 운영 안정성을 다뤄왔습니다. 운영 중 반복되는 불편을 직접 도구로 개선해 왔으며, 수집 실패를 웹에서 재시도하고 기록한 오류를 바탕으로 LLM이 장애 대응 방안을 추천하는 기능도 구현했습니다. 업무 밖에서도 지식 검색, 항공 특가 검증, 외국어 학습 등 관심 있는 문제를 해결하는 도구를 만들며 AI의 활용 가능성을 실험하고 있습니다.

이러한 경험을 바탕으로, AI가 실제 업무에 쓰이고 도입 이후에도 안정적으로 활용될 수 있도록 만드는 역할을 맡고 싶습니다. 이를 위해 AI가 어떤 근거로 답하고 어떤 작업을 수행하는지 확인할 수 있어야 하며, 사람이 검토하고 개입할 지점도 명확해야 한다고 생각합니다. 사내 위키 검색 시스템의 제안·도입 경험을 바탕으로 개발 중인 NexusWiki에서는 답변의 근거 검증, 사용 비용과 접근 권한 관리, 중요 문서 변경에 대한 사람의 승인을 구현하고 있습니다. 앞으로도 현업과 함께 문제를 정의하고, 실제 사용 중 드러나는 오류와 예외를 개선하며 업무에 정착시키는 과정까지 책임지겠습니다.

01. 업무 지식 검색에서 AI 통제로의 확장

사내 위키 검색 도입 전담 · 개인 프로젝트 NexusWiki 설계·구현·배포

여러 프로젝트에 팀원들이 교차 투입되면서 사양서 변경 사항을 갱신하고 업무 맥락을 전달하는 일이 반복됐습니다. 저는 고객사에 납품했던 사양서 기반 RAG에 위키를 결합하는 방안을 제안하고, 설계·구현부터 사내 플랫폼 도입까지 전담했습니다. 변경되는 업무 지식을 관리하면서 검색에도 활용하도록 구성했습니다.

이 문제의식은 개인 프로젝트 NexusWiki로 이어졌습니다. AI가 어떤 자료를 근거로 답했는지 확인할 수 있도록 원문·위키 각각의 벡터·어휘 검색을 결합한 4채널 하이브리드 검색과 RRF, 채널별 순위·기여도 디버그 뷰어를 구현했습니다. 인용 검증·보정, 비용 예약·정산, 중요 문서 변경 승인으로 AI의 품질·비용·권한을 통제했습니다.

OpenSpec 기반 SDD로 AI 에이전트 팀의 작업을 조율하고, 리뷰어 에이전트가 병합 전 명세와 접근 권한을 검증하도록 구성했습니다. 이 과정에서 발견된 워크스페이스 간 비용 기록 권한 결함을 수정·재검증하며, AI와 개발할 때도 명확한 인수 조건과 검증 절차가 필요하다는 점을 확인했습니다.

02. 글로벌 콘텐츠 플랫폼의 확장과 운영 안정화

국내 자동차 대기업 · Kotlin / Spring Boot 기반 백엔드 개발·운영

국가별 공급사와 데이터 특성이 다른 플랫폼에서 남미·일본 시장의 수집 파이프라인을 확장했습니다. 정적·동적·Push 수집 채널을 분리하고 헥사고날 구조로 공급사 확장에 대응했으며, ShedLock으로 다중 인스턴스의 수집기 중복 실행을 방지했습니다. 신규 시장 연동과 기존 수집의 안정성을 함께 고려했습니다.

5개 리전의 반복적인 점검을 줄이기 위해 kubectl과 AWS 자격증명으로 로그·지표·Pod 현황을 통합 조회하는 경량 모니터링 도구를 자체 개발했습니다. 수집 파이프라인 구축 경험을 바탕으로, 수집 실패 시 웹에서 Lambda 기반 수집 함수를 직접 재실행해 콘텐츠 공급사(CP)의 상태를 확인할 수 있도록 구현했습니다. 또한 오류 사례를 기록하고 이를 LLM에 질의해 장애 대응 방안을 추천받는 기능을 추가했습니다. OpenTelemetry·LGTM을 활용한 장애 원인 분석과 플레이북 문서화를 병행하며, 운영자가 상태 확인부터 재시도, 대응 방안 검토까지 이어갈 수 있도록 구성했습니다.

수집 파이프라인 확장과 중복 실행 방지, 통합 관제로 운영 점검을 효율화했습니다. 앞으로도 고객의 업무와 시스템 환경을 이해하고, 문제 해결의 판단 근거를 설명하며, 도입 이후 운영까지 활용할 수 있는 도구와 절차를 만드는 역할에 기여하고 싶습니다.
